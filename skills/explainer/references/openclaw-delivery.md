# OpenClaw: full artifact and compact companion

## Compose stock surfaces first

Read current advertised tools and installed stock docs before using them. Demonstrate existing operations on the requested surface before teaching them as proven. Documentation is not rendered acceptance. Never ask a fake question just to demo a control.

For a substantial explainer, author one set of facts, definitions, sources and (only if needed) decision options. Render the full responsive website artifact and compact inline companion from those same facts and exact artifact link. The full artifact may have its one dashboard; the companion must not create extra dashboards, tabs or pinned widgets merely to keep state.

- **Information only:** a short native chat summary and **Open full explainer** link suffice. No invented choice/recommendation. Use the exact saved URL returned by the host, not a guessed route. Leave an idempotent opener visible when viewer-local visibility is unavailable.
- **Human-owned blocking decision:** use native `ask_user` in the main session. Give 2–4 concise options, recommended first with `(Recommended)` suffix and a reason. Free-text Other is automatic; do not author it. Eligible plain chat replies also work. Do not ask approval for already authorised routine work. Link detail in surrounding chat. Keep question/run identity and stock saved question/answer history, queued/sending/failed/confirmed delivery and retry controls. A confirmed decision is not work completion.
- **Handoff/status:** reference existing `sessionKey` and available `runId`; use native session links and host hovercards. This is not an always-visible live inline status card. Do not copy state, derive a second status, poll, subscribe, add a plugin/proxy or modify core. Gateway run state, observer health and pull-request facts already own their meanings. A Sessions-board Done fallback/pinned column is not acceptance; unwatched health may be absent.

## Known stock boundaries

Stock `show_widget` inline HTML cannot read data APIs and has no host reply feedback. Do not invent an inline `session:progress` kind, props, grants or status fields. Documented `session:progress` with `props:{sessionKey:...}` is a dashboard renderer of agent-maintained saved progress, not automatic observer health and not proof of the requested inline surface. No dashboard proxy for inline persistence. The always-visible live inline handoff/status binding is a stock gap: state it plainly, with no implementation workaround and no new theme release gate.

For an explicitly requested nonblocking action on advertised inline HTML, `openclaw.prompt.send` is only a user-initiated REQUEST (visible/focused activation, at most 4000 characters, no slash command), never a decision, approval, accepted effect or completion receipt. Do not turn a local click/localStorage into a green Resolved badge. Existing native records confirm actor/time/outcome; preserve superseded history and retire stale actions through their owner. Failed/unknown delivery remains unresolved. Never rebuild native controls in HTML.

Stock navigation supports `dashboard.set_presentation` with `split` (chat alongside) and explicit `?dashboard=expanded` URLs only. No verified `?dashboard=split` URL exists. Do not use prompt/agent roundtrips where a native URL suffices, or broadcast layout changes for viewer-local clicks. If a direct split link is unavailable, use the native opener and explain the host split control. Do not promise automatic hiding: widget init exposes `controlUiBaseUrl`, not dashboard visibility. No parent DOM access, cross-origin tricks or width inference. Preserve other viewers.

## Check the actual container

Check full page and companion at 320, 390, 768 and wide containers, including a narrow pane on a wide desktop. Reflow diagrams into a readable vertical/stacked layout and wrap labels; do not shrink labels, clip controls or hide overflow as a fix. Hand-drawn figures need an authored narrow layout. Check keyboard, touch, 200% browser zoom, light/dark/auto, picker, popup, expanded canvas and actual regular/bold glyphs. Text resizing is not browser-zoom proof.

Record exact commit, host build, operating system, date, synthetic/live data and before/after screenshots. Fixtures are not authenticated stock-host proof. When a real decision exists, check view A answer → view B/reloaded history saved outcome; stale actions cannot duplicate effects and failed/unknown delivery stays honest. If host authoring is unavailable, give its owner the exact bundled file and these acceptance steps; do not disturb the active browser/dashboard.

Read installed stock references: `docs/tools/ask-user.md` (lifecycle/identity), `docs/tools/show-widget.md` (inline limits), `docs/web/chat.md` (session links), `docs/web/dashboards.md` (navigation), `docs/tools/progress-card.md` (dashboard composition), `docs/plugins/workboard.md` (state owners). These are composition instructions, not new runtime features.
